ทำไมไม่ต้องมีเซิร์ฟเวอร์หรือฐานข้อมูล

โปรแกรมอย่าง HIS ต้องมีเครื่องกลาง (เซิร์ฟเวอร์) ที่เก็บข้อมูลของทั้งโรงพยาบาล ทุกเครื่องต่อเข้าไปถามข้อมูล แต่โปรแกรมจัดซื้อทำงานคนละแบบ ทุกอย่างเกิดในเบราว์เซอร์บนเครื่องที่พี่เปิดอยู่

2 เรื่องที่ควรรู้เพิ่ม
  • ตอนเปิดโปรแกรมต้องต่ออินเทอร์เน็ต เพราะโปรแกรมโหลด "ตัวช่วยอ่าน Excel" (ชื่อ SheetJS) มาจากอินเทอร์เน็ต สิ่งที่โหลดเข้ามาคือตัวช่วย ไม่มีข้อมูลของพี่ถูกส่งออกไป
  • โปรแกรม "จำ" ไฟล์ที่ลากครั้งล่าสุดได้ โดยเก็บไว้ในเบราว์เซอร์ของเครื่องนั้นเอง ถ้าเปลี่ยนเครื่อง เปลี่ยนเบราว์เซอร์ หรือล้างประวัติเบราว์เซอร์ ต้องลากไฟล์ใหม่

ข้อยกเว้นมีเรื่องเดียว คือใบเสนอราคา บันทึก และเลขที่เอกสาร ที่หลายคนหลายเครื่องต้องใช้ชุดเดียวกัน เรื่องนี้เก็บไว้ที่กลาง อ่านต่อในบทถัดไป ส่วนไฟล์ HIS ยังอยู่ในเครื่องพี่เหมือนเดิม

ข้อมูลกลาง: ทุกเครื่องเห็นชุดเดียวกัน

เดิมแต่ละเครื่องจำประวัติใบเสนอราคาและเลขที่ถัดไปเอง ถ้าพี่ออกใบ W ที่โรงพยาบาล แล้วพี่เจี๊ยบออกใบ W จากอีกเครื่องในวันเดียวกัน ทั้ง 2 เครื่องไม่รู้จักกัน จึงออกเลขเดียวกันได้ และต้องทำใบซ้ำในอีกเครื่องเพื่อออก ภย. / ขย. / ย. ต่อ

ตอนนี้ทุกเครื่องต่อเข้า Google Sheet ของบัญชีคลัง ไฟล์เดียว เหมือนสมุดทะเบียนกลางที่วางไว้ที่เคาน์เตอร์ ใครจะออกเลขต้องมาเปิดสมุดเล่มเดียวกัน คนที่จองก่อนได้เลขนั้น คนถัดไปได้เลขถัดไป

ใช้ร่วมกันทุกเครื่อง

  • ประวัติใบเสนอราคา W / WM / WC พร้อมค่าในบันทึก ภ. / ข. / ย.
  • ตรวจรับ รย. / รยว. ที่ออกแล้ว
  • รายชื่อกรรมการและผู้ลงนาม
  • เลขที่ถัดไปของทุกเล่ม

ยังอยู่เฉพาะเครื่อง

  • ไฟล์ HIS ที่ลากเข้า
  • DATA Template (มีลายเซ็น จึงไม่ขึ้นที่กลาง)
  • ตราครุฑ
  • ตารางเดือนสำรองคงคลังและคงคลังย้อนหลัง

เชื่อมต่อเครื่อง (ทำครั้งเดียวต่อเครื่อง)

  1. เปิดโปรแกรมจากลิงก์เดิม กด Ctrl + F5 ให้ได้หน้าล่าสุด
  2. ที่แถบ ข้อมูลที่ใช้อยู่ กดปุ่ม ข้อมูลกลาง
  3. กรอก 3 ช่อง: ที่อยู่ web app และ รหัสเข้าถึง (น้องแป้งส่งให้ทางแชตส่วนตัว) กับ ชื่อผู้ใช้ / เครื่อง ตั้งเองให้รู้ว่าเครื่องไหน เช่น โอม-ที่ทำงาน ชื่อนี้จะโชว์ใน Sheet ว่าใครออกเลขไหน
  4. กด เชื่อมต่อ ปุ่มจะเปลี่ยนเป็น ข้อมูลกลาง · เชื่อมต่อแล้ว และประวัติใบเสนอราคาจะเป็นชุดเดียวกับเครื่องอื่น ข้อมูลเดิมของเครื่องนี้โปรแกรมเก็บสำเนาไว้ในเครื่อง ไม่ได้ลบ
ถ้าเห็นหน้าต่าง "ข้อมูลกลางยังว่าง"

กด ยกเลิก แล้วบอกน้องแป้ง หน้าต่างนี้ใช้ครั้งเดียวตอนย้ายข้อมูลเริ่มต้น ถ้าเห็นตอนเชื่อมต่อเครื่องของพี่ แปลว่าใส่ที่อยู่ผิด Sheet

ข้อมูลกลาง · ออฟไลน์อินเทอร์เน็ตหลุด ดูและแก้ได้ แต่ ออกเลขใหม่ไม่ได้ จนกว่าจะกลับมาออนไลน์

ข้อมูลกลาง (เฉย ๆ)เครื่องนี้ยังไม่ได้เชื่อมต่อ เลขที่ยังนับแยกในเครื่อง

หน้าต่างเตือนตอนส่งออก

โปรแกรมจองเลขที่กลางก่อนสร้างไฟล์ทุกครั้ง ถ้าจองไม่ได้ จะไม่สร้างไฟล์ แล้วเด้งหน้าต่าง ช่องเลขที่กะพริบสีแดง และมีกล่องแดงใต้ปุ่ม

หน้าต่างเขียนว่าเกิดอะไรขึ้นพี่ทำอะไร
ยังไม่ได้ส่งออก · (ชื่อเครื่อง) เพิ่งออกใบ Wอีกเครื่องเพิ่งใช้เลขนั้นไปก่อนใบเสนอราคา: โปรแกรมเปลี่ยนเป็นเลขถัดไปให้แล้ว กดส่งออกอีกครั้ง · บันทึก: แก้เลขตามที่บอกแล้วกดส่งออก
… ออกไปแล้วกับใบ …เลขที่พิมพ์เป็นของเอกสารใบอื่นใช้เลขถัดไปที่หน้าต่างบอก
… ต่ำกว่าเลขถัดไป และยังไม่มีบันทึกว่าใบนี้เคยส่งออกเลขนี้เปิดบันทึกเก่า (ก่อนมีข้อมูลกลาง) แล้วส่งออกพิมพ์ใบเดิมซ้ำ กด OK · ถ้าเป็นเอกสารใหม่ กด ยกเลิก แล้วใช้เลขที่บอก
เล่ม … ยังไม่มีเลขเริ่มในข้อมูลกลางเป็นใบแรกของเล่มนั้นในระบบใหม่ ทุกเครื่องจะนับต่อจากเลขนี้เทียบกับเล่มจริงก่อน ตรงแล้วกด OK · ไม่ตรง กด ยกเลิก แก้เลขแล้วส่งออกอีกครั้ง
ติดต่อข้อมูลกลางไม่ได้อินเทอร์เน็ตหลุดต่ออินเทอร์เน็ตแล้วกดส่งออกอีกครั้ง
ควรรู้เพิ่ม
  • พิมพ์เอกสารเดิมซ้ำได้ เปิดใบเดิมแล้วส่งออกอีกครั้ง ใช้เลขเดิม ไม่จองเลขใหม่
  • ลบใบเสนอราคาได้ เลือกใบในช่อง "ใบที่ส่งออกแล้ว" แล้วกด "ลบใบนี้" ทุกเครื่องจะไม่เห็นใบนั้น เลขที่ของใบนั้นไม่นำกลับมาใช้ ถ้าใบนั้นออกบันทึกไปแล้ว โปรแกรมเตือนก่อน (ลบผิด ขอให้ผู้ดูแลกู้คืนจาก Sheet ได้)
  • ใบที่มีป้าย "ออกซ้ำ" คือใบเลขเดียวกันที่เคยทำจาก 2 เครื่องก่อนมีข้อมูลกลาง เก็บไว้ทั้ง 2 ใบ ไม่มีอะไรหาย
  • ไม่ต้องกู้คืนไฟล์สำรองเพื่อย้ายงานข้ามเครื่องแล้ว ตอนเชื่อมต่ออยู่ ปุ่มกู้คืนข้อมูลจะไม่ทำงาน กันไม่ให้ไฟล์เก่าทับงานของเครื่องอื่น ปุ่มสำรองข้อมูลยังใช้ได้
  • เลขที่ข้ามได้ ไม่จำเป็นต้องครบทุกเลข เช่น สร้างไฟล์ไม่สำเร็จหลังจองเลข เลขนั้นข้ามไป
ห้าม
  • ห้ามแก้ใน Google Sheet ด้วยมือ โปรแกรมเป็นคนเขียน ถ้าแก้เอง เลขที่หรือใบอาจไม่ตรงกับทุกเครื่อง เปิดดูได้อย่างเดียว
  • ห้ามส่งรหัสเข้าถึงในกลุ่ม LINE ใครมีที่อยู่กับรหัสก็เข้าข้อมูลกลางได้ ถ้ารหัสหลุด บอกน้องแป้งให้เปลี่ยนรหัส แล้วทุกเครื่องใส่รหัสใหม่

ระบบแบบนี้เรียกว่าอะไร

ข้อมูลกลางมี 3 ชิ้นทำงานต่อกัน หน้าโปรแกรมอยู่บน GitHub ข้อมูลอยู่ใน Google Sheet และตรงกลางมีโปรแกรมเล็ก ๆ ของ Google (Apps Script) เป็นทางเข้า หน้าโปรแกรมไม่ได้เปิด Sheet เอง แต่ส่งคำขอไปที่ทางเข้านี้พร้อมรหัสเข้าถึง แล้วรอคำตอบกลับมา

ทางเข้าแบบนี้ภาษาคอมพิวเตอร์เรียกว่า API ทั้งระบบเรียกรวม ๆ ว่า หน้าบ้านแบบ static ที่คุยกับ API แบบ serverless และใช้ Google Sheet เป็นฐานข้อมูล

เทียบกับงานที่พี่ทำทุกวันคือ การเบิกยาจากคลัง ห้องจ่ายยาไม่ได้เดินเข้าไปหยิบของในคลังเอง แต่ยื่นใบเบิกที่ช่องเบิก เจ้าหน้าที่คลังตรวจลายเซ็น หยิบของ ลงบัญชี แล้วส่งของกลับมา

ตอนพี่กดส่งออกใบ W เกิดอะไรขึ้น (ตามเลขในภาพ)

  1. ส่งคำขอ หน้าโปรแกรมส่งข้อความสั้น ๆ ผ่านอินเทอร์เน็ตไปที่ที่อยู่ /exec ว่า "ขอจองเลข W121-70" แนบรหัสเข้าถึงและชื่อเครื่องไปด้วย
  2. ตรวจรหัส web app เทียบรหัสกับที่เก็บไว้ ไม่ตรงก็ตอบกลับว่ารหัสผิด ไม่แตะ Sheet เลย
  3. ล็อกแล้วเช็กเลข ให้คำขอเดียวทำงานในเวลาเดียวกัน แล้วดูว่า W121-70 ยังเป็นเลขถัดไปจริงไหม ถ้าพี่เจี๊ยบกดส่งออกพร้อมกัน คำขอที่มาทีหลังต้องรอ แล้วจะพบว่าเลขนั้นถูกใช้ไปแล้ว จึงไม่มีทางได้เลขเดียวกัน
  4. เขียนลง Sheet ถ้าเลขว่าง เลื่อนเลขถัดไปของเล่ม W และจดในแท็บบันทึกการแก้ว่าเครื่องไหนจองเลขไหน เมื่อไร ถ้าเลขถูกใช้ไปแล้ว ไม่เขียนอะไร
  5. ตอบกลับ ส่งคำตอบกลับมาเป็นข้อความรูปแบบ JSON จองได้ตอบว่า "status":"ok" เลขถูกใช้ไปแล้วตอบว่า "status":"conflict" พร้อมชื่อเครื่องที่ใช้ไป (คือหน้าต่างเตือนในบทที่แล้ว)
  6. ทำไฟล์ จองได้แล้วหน้าโปรแกรมจึงสร้างไฟล์ Excel บนเครื่องพี่ และเก็บสำเนาไว้ใน IndexedDB ของเครื่อง

เหมือนช่องเบิก รับใบเบิกตามแบบฟอร์มเท่านั้น

Back end · Serverless

หลังบ้านที่ไม่ต้องมีเครื่องเอง

Apps Script รันบนเครื่องของ Google เปิดทำงานเมื่อมีคำขอเข้ามา เราไม่ต้องตั้งหรือดูแลเซิร์ฟเวอร์ ทำงานในนามบัญชีคลังเสมอ ไม่ว่าใครเป็นคนกด

เหมือนใช้คลังของ รพ. ที่มีอยู่แล้ว ไม่ต้องสร้างคลังเอง

Database

ฐานข้อมูล

ที่เก็บข้อมูลตัวจริง ของเราใช้ Google Sheet ซึ่งพอสำหรับข้อมูลหลักร้อยถึงหลักหมื่นแถว และเปิดดูด้วยตาได้

เหมือนชั้นวางและบัญชีคุมคลัง

JSON

รูปแบบคำตอบ

ข้อความที่จัดเป็นหัวข้อ : ค่า ให้โปรแกรมอ่านได้ทันที เช่น "ok":true

เหมือนใบตอบรับที่มีช่องให้กรอกตายตัว

ล็อก

ทำได้ทีละคำขอ คำขอที่มาพร้อมกันต้องต่อคิว ป้องกันเลขที่ซ้ำ

เหมือนสมุดทะเบียนเล่มเดียว คนอื่นต้องรอจนคนที่ถือเขียนเสร็จ

Cache + sync

สำเนาในเครื่อง

แต่ละเครื่องเก็บสำเนาไว้ใน IndexedDB เปิดเร็วและเน็ตหลุดก็ยังดูได้ แล้วซิงก์ (sync) กับ Sheet เมื่อออนไลน์

เหมือนสต็อกย่อยในห้องจ่าย ที่เติมจากคลังเป็นรอบ ๆ

ทำไมเรียกว่า web app ทั้งที่ไม่มีหน้าจอ

ใน Google คำว่า "web app" หมายถึง "ให้ script นี้มีที่อยู่บนเว็บที่รับคำขอได้" ตอนน้องแป้งกด Deploy → Web app จึงได้ที่อยู่ /exec มา web app ของเราไม่มีหน้าจอ ตอบเป็นข้อมูลอย่างเดียว จึงทำหน้าที่เป็น API หน้าจอที่พี่ใช้อยู่บน GitHub Pages ถ้าเปิดที่อยู่ /exec ในเบราว์เซอร์ตรง ๆ จะเห็นแค่ข้อความ JSON สั้น ๆ

สรุปเป็นประโยคเดียว ใช้บอก AI หรือคนที่ทำโปรแกรมเป็น ว่าระบบของเราเป็นแบบไหน

(secured with an API key), stores shared data in a Google Sheet,

เขียน PRD ก่อนสั่ง AI

PRD ย่อมาจาก Product Requirements Document คือเอกสารที่บอกว่าโปรแกรมต้องทำอะไร เขียนก่อนให้ AI เริ่มสร้าง

พี่คุ้นกับงานจัดซื้ออยู่แล้ว PRD ก็คือ TOR หรือสเปกของโปรแกรม สเปกชัด ของที่ได้ก็ตรง สเปกคลุมเครือ ต้องตีกลับแก้กันหลายรอบ AI ก็เหมือนผู้ขาย ทำตามที่เขียนไว้ ไม่ได้ทำตามที่เราคิดในใจ

ได้ตรงใจตั้งแต่รอบแรก

เริ่มแชทใหม่ได้ทุกเมื่อ

แค่บอก AI ให้อ่าน PRD.md ไม่ต้องอธิบายใหม่ตั้งแต่ต้น

ใช้ได้กับทุกเครื่อง ทุก AI

เปลี่ยนเครื่อง หรือโควตาหมดแล้วไปใช้แชทในเว็บ ก็ใช้ PRD เดิมได้

สร้างไฟล์ PRD.md

  1. ใน Antigravity คลิกขวาที่ว่างในรายการไฟล์ด้านซ้าย เลือก New File ตั้งชื่อ PRD.md
  2. กดคัดลอกแบบฟอร์มด้านล่าง วางลงในไฟล์ เติมข้อความในวงเล็บ [ ] แล้วกด Ctrl + S เพื่อเซฟ

ไฟล์ .md คือไฟล์ข้อความธรรมดา เครื่องหมาย # คือหัวข้อ - คือข้อย่อย และ [ ] คือช่องติ๊กที่ยังไม่เสร็จ ข้อ 8 เป็นข้อกำหนดที่ใช้กับทุกโปรแกรม ไม่ต้องแก้

# PRD: เช็กยาใกล้หมดอายุ

## 1. ปัญหาที่อยากแก้
ทุกเดือนต้องเปิด inventory_exp.xls แล้วไล่หา lot ที่ใกล้หมดอายุเอง ใช้เวลานานและพลาดได้

## 2. คนใช้
เภสัชกรคลังยา 2 คน เปิดดูเดือนละ 1–2 ครั้ง

## 3. ข้อมูลที่ใช้
ไฟล์: inventory_exp.xls (export จาก HIS)
คอลัมน์:
- meditem = รหัสยา
- expdate = วันหมดอายุ
- lotno = เลข lot
- sumqty = จำนวนคงเหลือ (กล่อง)
- unitcost = ราคาทุนต่อกล่อง
- packqty = จำนวนบรรจุต่อกล่อง
ตัวอย่างข้อมูล (แต่งขึ้น ไม่ใช่ข้อมูลจริง):
1001, 2027-01-31, A123, 20, 150, 100
1002, 2026-12-15, B456, 5, 820, 10
1003, 2028-06-30, C789, 12, 95, 500

## 4. สิ่งที่โปรแกรมต้องทำ
- [ ] ลากไฟล์ inventory_exp.xls มาวางแล้วอ่านได้
- [ ] แสดงเฉพาะ lot ที่หมดอายุภายใน 6 เดือนนับจากวันนี้
- [ ] รวมมูลค่ายาที่ใกล้หมดอายุทั้งหมด
- [ ] ค้นหาด้วยรหัสยาได้

## 5. วิธีคำนวณและเงื่อนไข
- มูลค่า = sumqty × unitcost
- เหลือไม่ถึง 3 เดือน = แถวสีแดง, 3–6 เดือน = แถวสีเหลือง
- ยอดติดลบให้นับเป็น 0

## 6. หน้าจอ
- ด้านบน: จำนวน lot ที่ใกล้หมดอายุ และมูลค่ารวม
- ตาราง: รหัสยา, lot, วันหมดอายุ, เหลืออีกกี่วัน, จำนวน (กล่อง), มูลค่า
- เรียงจากหมดอายุก่อนไปหลัง

## 7. ยังไม่ทำในรอบนี้
- ชื่อยา (ต้องใช้ Meditem.xls เพิ่ม ทำรอบหน้า)
- ส่งออก Excel

## 8. ข้อกำหนดที่ใช้ทุกโปรแกรม (ไม่ต้องแก้)
- เป็นไฟล์ HTML ไฟล์เดียว ชื่อ index.html รวม CSS และ JavaScript ไว้ในไฟล์เดียว
- เปิดได้ด้วยการดับเบิลคลิกในเบราว์เซอร์ ไม่ใช้เซิร์ฟเวอร์ ไม่ใช้ฐานข้อมูล
- ข้อความบนหน้าจอเป็นภาษาไทย
- ผู้ใช้ลากไฟล์ Excel มาวางเอง ห้ามใส่ข้อมูลจริงไว้ในไฟล์ HTML
- ข้อมูลที่ลากมาวาง ต้องไม่ถูกส่งออกไปที่ไหน

## 9. ตรวจยังไงว่าเสร็จ
- [ ] ลากไฟล์ที่มี 3 แถวตัวอย่างข้างบน ถ้าเปิดวันที่ 2026-10-05
      ต้องเห็น 2 lot: B456 สีแดง (เหลือ 71 วัน) และ A123 สีเหลือง (เหลือ 118 วัน)
- [ ] C789 ต้องไม่แสดง เพราะเหลือเกิน 6 เดือน
- [ ] มูลค่ารวมต้องเป็น 7,100 บาท (5 × 820 + 20 × 150)
ข้อ 9 สำคัญที่สุด

ใส่ตัวอย่างที่รู้คำตอบล่วงหน้า เช่น มูลค่ารวมต้องได้ 7,100 บาท พอ AI สร้างเสร็จ พี่ลองแล้วเทียบได้ทันทีว่าคำนวณถูกไหม ไม่ต้องเชื่อ AI อย่างเดียว

ไม่รู้จะเขียนยังไง ให้ AI ช่วยถาม

ถ้านึกไม่ออกว่าจะเติมอะไร ให้สร้าง PRD.md ด้วยแบบฟอร์มเปล่าไว้ก่อน แล้วใช้คำสั่งนี้ AI จะถามทีละข้อเหมือนสัมภาษณ์ แล้วเขียนลงไฟล์ให้ การคุยรอบนี้ใช้โควตาบ้าง แต่น้อยกว่าการให้ AI เขียนโค้ดผิดแล้วแก้หลายรอบมาก

ห้ามลืม

ตัวอย่างข้อมูลใน PRD ต้องเป็นข้อมูลที่แต่งขึ้นเท่านั้น ห้ามคัดลอกแถวจริงจากไฟล์ของโรงพยาบาล

สร้างโปรแกรมด้วย Antigravity กับ AI

พี่ไม่ต้องพิมพ์โค้ดเอง ให้ AI อ่าน PRD แล้วเขียนให้ งานของพี่คือ ดูแล PRD ให้ชัด แล้ว ลองใช้ตามข้อ 9 ทำซ้ำไปเรื่อย ๆ จนได้โปรแกรมที่ต้องการ

  1. สร้างโฟลเดอร์ใหม่ สำหรับโปรแกรมนี้ เช่น Documents\เช็กยาใกล้หมดอายุ หนึ่งโปรแกรมใช้หนึ่งโฟลเดอร์ จะได้ไม่ปนกัน
  2. เปิด Antigravity กด File → Open Folder แล้วเลือกโฟลเดอร์นั้น
  3. เขียน PRD.md ตามบทที่แล้ว
  4. ในช่องแชทของ AI วาง คำสั่งที่ 1 ด้านล่าง AI จะอ่าน PRD แล้วสร้างไฟล์ index.html ในโฟลเดอร์ให้
  5. เปิดดูผล คลิกขวาที่ index.html ในรายการไฟล์ด้านซ้าย เลือก Reveal in File Explorer แล้วดับเบิลคลิก ไฟล์จะเปิดใน Chrome หรือ Edge แล้วลองตามข้อ 9 ของ PRD ทีละข้อ
  6. ยังไม่ตรง ใช้คำสั่งที่ 2 หรือ 3 อยากได้ความสามารถเพิ่ม เพิ่มลงใน PRD ข้อ 4 ก่อน แล้วค่อยใช้คำสั่งที่ 2 แก้เสร็จแล้วกลับไปที่เบราว์เซอร์ กด F5 เพื่อโหลดใหม่
ห้ามลืม

อย่าวางไฟล์ Excel ข้อมูลจริงไว้ในโฟลเดอร์ที่เปิดใน Antigravity เพราะ AI อ่านไฟล์ในโฟลเดอร์ได้ เก็บไฟล์จริงไว้ที่อื่น แล้วลากมาวางในโปรแกรมตอนใช้งานเท่านั้น

คำสั่งสำหรับแชท (คัดลอกไปใช้ได้เลย)

1 · สร้างโปรแกรมจาก PRD
อ่านไฟล์ PRD.md ในโฟลเดอร์นี้
แล้วสร้างโปรแกรมเป็นไฟล์ index.html ตาม PRD ทุกข้อ
ถ้าข้อไหนไม่ชัด ให้ถามก่อนเริ่มเขียน
เขียนเสร็จแล้ว บอกวิธีทดสอบตามข้อ 9 ของ PRD
2 · ขอแก้หรือเพิ่มทีละเรื่อง
อ่าน PRD.md ก่อน
แล้วในไฟล์ index.html ช่วยแก้เรื่องเดียว:
[เช่น เพิ่มปุ่ม "ส่งออก Excel" ใต้ตาราง]
ส่วนอื่นไม่ต้องเปลี่ยน
แก้เสร็จแล้ว อัปเดต PRD.md ให้ตรงกับโปรแกรมด้วย
3 · แจ้งว่าไม่ทำงาน
เปิดไฟล์แล้ว [เกิดอะไรขึ้น เช่น หน้าจอว่าง / กดปุ่มแล้วไม่มีอะไรเกิดขึ้น]
ที่ต้องการคือ [ผลที่อยากเห็น เช่น ตามข้อ 9 ใน PRD.md]
ข้อความ error ใน Console:
[วางข้อความสีแดงตรงนี้]

วิธีดูข้อความ error: เปิดไฟล์ในเบราว์เซอร์ กด F12 เลือกแท็บ Console ถ้ามีข้อความสีแดง ให้คลุมดำ คัดลอก แล้ววางในคำสั่งที่ 3 ข้อความนี้ช่วยให้ AI แก้ถูกจุดในรอบเดียว ไม่ต้องเดาหลายรอบ

ดับเบิลคลิกแล้วไฟล์ไม่เปิดในเบราว์เซอร์: คลิกขวาที่ไฟล์ เลือก Open with แล้วเลือก Chrome หรือ Edge

ประหยัดโควตา AI แผนฟรี

ทุกข้อความที่ส่ง และทุกไฟล์ที่ AI ต้องอ่าน กินโควตาทั้งหมด ยิ่งยาวยิ่งหมดเร็ว 5 ข้อนี้ช่วยให้ใช้ได้นานขึ้น

  1. ขอทีละเรื่อง แต่อธิบายให้ครบในข้อความเดียว การคุยไปกลับหลายรอบเพื่อเติมรายละเอียดกินโควตามากกว่า
  2. เปลี่ยนเรื่องเมื่อไหร่ ให้เริ่มแชทใหม่ แชทยาว ๆ ทำให้ AI ต้องอ่านเรื่องเก่าทั้งหมดซ้ำทุกครั้งที่ตอบ
  3. ให้ PRD.md ตรงกับโปรแกรมเสมอ เวลาเริ่มแชทใหม่ บอก AI ว่า "อ่าน PRD.md ก่อน" AI จะเข้าใจโปรแกรมทันทีโดยไม่ต้องอ่านโค้ดทั้งไฟล์ (Dashboard จัดซื้อใช้ไฟล์ README.md ทำหน้าที่นี้)
  4. งานเล็กแก้เอง เปลี่ยนคำ เปลี่ยนสี เปลี่ยนตัวเลข ใช้ Ctrl + F หาแล้วแก้ในหน้าต่างโค้ดของ Antigravity ได้เลย ไม่เสียโควตา
  5. สำรองไฟล์ก่อนแก้ครั้งใหญ่ คัดลอกไฟล์ไว้อีกชุด ตั้งชื่อตามวันที่ เช่น dashboard-2569-10-05.html ถ้า AI แก้พัง จะย้อนกลับได้ทันที โดยไม่ต้องเสียโควตาให้ AI ซ่อม

เมื่อโควตาหมด

รอโควตากลับมา

  • ระหว่างรอ ยังเปิดโปรแกรมที่ทำไว้แล้วใช้งานได้ตามปกติ เพราะโปรแกรมไม่ต้องพึ่ง AI ตอนใช้งาน
  • ใช้เวลานี้เขียนสิ่งที่อยากแก้ลงใน PRD.md รอบหน้าสั่ง AI ได้ในข้อความเดียว

ใช้แชท AI ในเว็บ (ฟรี)

  • เช่น gemini.google.com, chatgpt.com, claude.ai
  • คัดลอกเนื้อหาใน PRD.md ไปวางในแชท แล้วขอให้เขียน index.html ตาม PRD AI จะตอบเป็นโค้ด กดคัดลอก วางลงใน index.html ใน Antigravity แล้วเซฟ
  • เหมาะกับโปรแกรมเล็ก ไฟล์ใหญ่อย่าง Dashboard จัดซื้ออาจยาวเกินที่แชทฟรีรับได้

แยกลิงก์โปรแกรมจัดซื้อออกเป็นส่วน ๆ

https://ขึ้นต้นลิงก์ tamonwan-chanชื่อบัญชี GitHub ของน้องแป้ง .github.io/บริการ GitHub Pages Procurement-RJ-2-Dashboard/ชื่อโปรเจกต์ mockup/dashboard-mockup.htmlโฟลเดอร์และชื่อไฟล์

ชื่อบัญชีอยู่หน้าลิงก์เหมือนบ้านเลขที่ ลิงก์ของโปรแกรมจะขึ้นต้นด้วยชื่อบัญชีของคนที่เอาโปรแกรมขึ้น GitHub เสมอ ถ้าวันหนึ่งพี่มีบัญชี GitHub ของตัวเองแล้วเอาโปรแกรมขึ้นไป ลิงก์ก็จะขึ้นต้นด้วยชื่อบัญชีของพี่แทน

GitHub คืออะไร และทำไมน้องแป้งถึงใช้

GitHub คือเว็บสำหรับเก็บโค้ด คล้าย Google Drive แต่จำทุกเวอร์ชันที่เคยแก้ ถ้าแก้พังก็ย้อนกลับไปเวอร์ชันก่อนได้ ประวัติการแก้ของโปรแกรมจัดซื้อมี 20 ครั้งแล้ว ทุกครั้งย้อนดูได้

เหตุผลหลักที่ใช้คือ น้องแป้งแก้โปรแกรมจากหลายเครื่อง แก้เสร็จที่เครื่องไหนก็ส่งขึ้น GitHub (เรียกว่า push) แล้วอีกเครื่องดึงลงมา (เรียกว่า pull) ทุกเครื่องได้ไฟล์ล่าสุดตรงกัน ไม่ต้องส่งไฟล์ผ่านไลน์หรือ USB และไม่สับสนว่าไฟล์ไหนใหม่กว่า

GitHub ยังมีบริการชื่อ GitHub Pages ที่ทำให้ไฟล์ HTML บน GitHub เปิดเป็นเว็บได้ฟรีผ่านลิงก์ พี่โอมเลยเปิดโปรแกรมได้เลยโดยไม่ต้องมีไฟล์ในเครื่อง และได้เวอร์ชันล่าสุดเสมอ

อะไรอยู่บน GitHub และอะไรไม่อยู่

อยู่บน GitHub

  • โค้ดของโปรแกรม (ไฟล์ HTML)
  • คู่มือ README
  • เป็นแบบสาธารณะ คนที่มีลิงก์เห็นโค้ดได้ แต่โค้ดไม่มีข้อมูลยาหรือข้อมูลผู้ป่วย

ไม่อยู่บน GitHub

  • ไฟล์ Excel ข้อมูลจริงของ รพ. ตั้งค่าไว้ไม่ให้อัปโหลดขึ้นไป
  • ไฟล์ที่พี่ลากมาวางในหน้าโปรแกรม อยู่ในเบราว์เซอร์ของพี่เท่านั้น
  • ข้อมูลกลาง (ใบเสนอราคา บันทึก เลขที่) อยู่ใน Google Sheet ของบัญชีคลัง ไม่ใช่ GitHub ที่อยู่และรหัสเข้าถึงก็ไม่อยู่ในโค้ด

คำศัพท์

HTML
ภาษาที่บอกโครงของหน้าจอ ไฟล์นามสกุล .html
CSS
ส่วนที่บอกหน้าตา สี ขนาด ระยะห่าง
JavaScript
ส่วนที่ทำงาน คำนวณ อ่านไฟล์ ตอบสนองการกดปุ่ม
เบราว์เซอร์
โปรแกรมเปิดเว็บ เช่น Chrome, Edge
เซิร์ฟเวอร์
เครื่องกลางที่เก็บข้อมูลหรือโปรแกรมให้เครื่องอื่นมาเรียกใช้ เช่น เครื่องของ HIS
ฐานข้อมูล
ที่เก็บข้อมูลจำนวนมากแบบเป็นระบบ มักอยู่บนเซิร์ฟเวอร์
ข้อมูลกลาง
Google Sheet ของบัญชีคลังที่ทุกเครื่องใช้ร่วมกัน เก็บใบเสนอราคา บันทึก และเลขที่ถัดไป
web app
โปรแกรมเล็ก ๆ (Apps Script) ที่ผูกกับ Sheet เป็นทางเข้าเดียวที่หน้าโปรแกรมใช้อ่านและเขียน Sheet ที่อยู่ลงท้ายด้วย /exec
รหัสเข้าถึง
รหัสที่ทุกเครื่องต้องใส่ตอนเชื่อมต่อ ไม่มีรหัสก็เข้าข้อมูลกลางไม่ได้ ภาษาคอมพิวเตอร์เรียกว่า API key
API
ทางเข้าที่โปรแกรมหนึ่งส่งคำขอไปให้อีกโปรแกรมหนึ่งทำงานแล้วตอบกลับ ไม่มีหน้าจอ เหมือนช่องเบิกของคลัง
Front end / Back end
หน้าบ้าน (ส่วนที่คนเห็นและกด) / หลังบ้าน (ส่วนที่เก็บและจัดการข้อมูล)
Serverless
หลังบ้านที่รันบนเครื่องของผู้ให้บริการ เช่น Google เราไม่ต้องมีหรือดูแลเซิร์ฟเวอร์เอง
JSON
รูปแบบข้อความแบบหัวข้อ : ค่า ที่ API ใช้ตอบกลับ
Sync
ทำให้สำเนาในเครื่องกับข้อมูลกลางตรงกัน
PRD
เอกสารบอกว่าโปรแกรมต้องทำอะไร เหมือน TOR หรือสเปกตอนจัดซื้อ เขียนก่อนให้ AI สร้าง
ไฟล์ .md
ไฟล์ข้อความธรรมดาที่ใช้ # ทำหัวข้อ และ - ทำข้อย่อย
GitHub
เว็บเก็บโค้ดที่จำทุกเวอร์ชัน
Repository
โปรเจกต์หนึ่งโปรเจกต์บน GitHub คล้ายโฟลเดอร์หนึ่งโฟลเดอร์
Push / Pull
ส่งไฟล์ที่แก้ขึ้น GitHub / ดึงไฟล์ล่าสุดลงมาที่เครื่อง
GitHub Pages
บริการฟรีของ GitHub ที่ทำให้ไฟล์ HTML เปิดเป็นเว็บผ่านลิงก์ได้
Console
หน้าต่างที่เปิดด้วย F12 ในเบราว์เซอร์ แสดงข้อความ error ของโปรแกรม
โควตา / Token
ปริมาณการใช้ AI ที่แผนฟรีให้ ยิ่งข้อความและไฟล์ที่ส่งยาว ยิ่งใช้มาก
