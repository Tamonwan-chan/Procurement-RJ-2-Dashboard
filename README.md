# Dashboard จัดซื้อ พี่โอม

ระบบติดตามคลังยาและการจัดซื้อของห้องยา — ลากไฟล์ Excel รายการยาจัดหามาวาง แล้วดูแดชบอร์ดสรุปทันที ทำงานทั้งหมดในเบราว์เซอร์ ไม่ต้องมีเซิร์ฟเวอร์หรือติดตั้งอะไรเพิ่ม

## สถานะปัจจุบัน

`mockup/dashboard-mockup.html` ใช้งานได้จริงแล้วในระดับ prototype — ลากไฟล์ `.xlsx` รูปแบบเดียวกับที่ใช้อยู่ (ชีต "รายการต้องจัดซื้อ", "คงคลัง", "ชั้น G", "ชั้น 1", "จัดหา", "ทะเบียน") มาวางแล้วจะแสดงแดชบอร์ดจากข้อมูลจริงทันที ก่อนวางไฟล์จะแสดงข้อมูลตัวอย่าง 15 รายการไว้ให้ดูหน้าตาก่อน

ยังไม่ตัดสินใจว่าจะทำเป็นเว็บแอปโลคัลแบบไฟล์เดียว (ปัจจุบัน) ต่อไปเลย หรือจะทำเป็นระบบที่มีฐานข้อมูล/บันทึกประวัติการ import — รอดูผลตอบรับจากพี่โอมก่อน

## โครงสร้างไฟล์จริงที่ใช้อยู่ (จากไฟล์ตัวอย่างที่ส่งมา)

ไฟล์ Excel มี 11 ชีต โปรแกรมใช้ 6 ชีตนี้ จับคู่ข้อมูลกันด้วย hospcode:

| ชีต | ใช้ทำอะไร | จำนวนแถว |
|---|---|---|
| รายการต้องจัดซื้อ | รายการยาหลัก (hospcode, generic, tradename, unitprice, list want ฯลฯ) | 4,326 |
| คงคลัง | สต็อกคลังกลาง + มูลค่ารวมต่อรายการ + กลุ่ม (A-Z) | 425 |
| ชั้น G / ชั้น 1 | สต็อกรายห้อง (stkqty, costrate) | 974 / 1,215 |
| จัดหา | lowrate / highrate / userate ต่อรายการ | 291 |
| ทะเบียน | รหัส GPU (gpucode) ต่อรายการ | 9,006 |
| drugcat | บัญชียาแม่บท (ยังไม่ได้ใช้ในหน้าแดชบอร์ดรอบนี้) | 4,335 |

## ประเด็นที่รอยืนยันจากพี่โอม

ดูรายละเอียดพร้อมอ้างอิง PRD ในหน้า mockup (ส่วนท้ายสุด) — สรุปคร่าว ๆ:
1. Import ซ้ำได้ทุกครั้งหรือต้อง fix โครงสร้าง (ปัญหา hospcode ไม่เรียงลำดับ)
2. เผื่อห้องจ่ายยาเพิ่มในปี 2570–2571 กี่ห้อง
3. สัดส่วน ED/NED นับที่รายการยา (hospcode) หรือรหัส GPU — ในไฟล์จริงมีรหัส GPU ให้แค่บางรายการ
4. "ชื่อกลุ่ม" (A-Z) ในชีตคงคลัง คือกลุ่มเดียวกับที่จะใช้เป็น gpscode หรือไม่ ถ้าไม่ใช่ต้องขอตารางแม่บทมาจับคู่เพิ่ม
5. คอลัมน์ lowrate/highrate/userate หมายถึงอะไรกันแน่ (mockup ตั้งสมมติฐานว่าเป็นเกณฑ์ต่ำสุด-สูงสุด เทียบกับอัตราการใช้จริง)
6. คลังกลาง/หน่วยย่อยมีหน่วยนับต่างกันตามรายการ (เม็ด/ขวด/กล่อง) ต้องการให้แปลงเป็นหน่วยจัดหาเดียวกันทั้งระบบหรือไม่
7. drug cat ต้องการ key เข้าเองอย่างเดียว หรือรองรับ import ทับบัญชีเดิมด้วย
